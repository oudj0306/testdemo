# 本地视觉识别：质量优先

本轮实现本地视觉转写与核验，不训练新模型。题目定位仍复用原模板，评分仍按原评分模式执行：选择题本地填涂，固定答案规则判分，主观题调用已配置的文本评分模型。识别模型不会收到题目答案或评分标准。

## 启动

在项目目录 PowerShell 首次运行（需要联网下载公开软件和权重）：

```powershell
.\setup-local-vision.ps1
```

启用本地视觉设置后，以后一个终端运行：

```powershell
.\start-optimization.ps1 -Port 8001
```

启动器自动启动并管理自己的本地视觉服务；关闭批改服务时清理自己启动的服务。也可先在另一个终端运行 `.\start-local-vision.ps1` 独立管理；启动器复用已有服务并不关闭它。

支持 Windows 自带的 PowerShell 5.1，不要求另装 PowerShell 7。启动器与安装器使用当前 PowerShell 安装的完整路径，支持目录包含空格，并将当前会话的有效执行策略传给子进程，不修改系统执行策略。

工作台“识别加速”中选择“本地视觉模型 · 两次转写核验”，保存。仅作用于启用了答题卡位置模板的答卷；单独开启远程评分配置不会启用此路径。停用本地视觉设置即可恢复原 OCR 路径。开启后旧的可靠作答与人工校正继续复用，尚未可靠识别题目才使用新模型。

首次准备默认 `qwen3-vl:4b-instruct`（官方 Ollama 库 Q4_K_M 量化）。8GB RTX 4060 上使用单个模型、单次并发，8192 上下文。实际速度和稳定性需按图片与输出长度验证，不保证任意输入都能放进显存。量化不等于蒸馏。

便携运行时固定为 Ollama 0.40.9，来自官方 GitHub Release；为避免下载不使用的大型 CUDA 组件，只提取基础与 Vulkan GPU 文件。安装器检查官方 HTTPS 分段响应、每个 ZIP 成员大小及 CRC32，未声称已完成完整 ZIP SHA256 校验。不修改系统注册表或原项目环境。可复用系统 GPU 驱动的 Vulkan 支持；GPU 实际选用情况查看服务日志与 `ollama ps`。

运行时与模型保存在 `data/local-vision/`，缓存与含学生作答的诊断也仅保存在忽略的 `data/`，不入 Git。服务仅监听 127.0.0.1:11435，关闭云端能力；应用拒绝远程地址、HTTP 重定向和 cloud 模型标签，不携带评分 API 密钥。

## 转写及验收边界

- 中文手写、代码和公式逐字转写。代码保留原始缩进、错误变量和运算符；不纠错、不补全、不执行学生代码。
- 流程图返回节点与有向连接（含分支标签）。节点重复、悬空箭头、预期流程图未提取连接均不能自动采用。真实测试发现同一模型两次都漏掉实际处理框，因此 v2 对流程图始终保留候选、要求人工核对结构，不凭两次一致自动出分。
- 同一模型分别对原始裁切及灰度对比度增强裁切进行两次转写，第二次不提供第一次结果。文字与代码只接受结构有效、无明确不确定项、两次内容一致的结果；流程图另有人工核对门槛。跨区域代码/流程图最多3个区域按同题同时输入，避免各区独立重置缩进或节点编号；超过此限制保留缺分。
- 两次同模型结果具有相关性，一致不能证明正确，也不称为独立双模型评审；保留抽检提示。生成模型仍可能重复同一错误或自行纠错，需要真实人工转写对照。
- 不把模型自报置信度当概率，不人为填入 0.99。通过转写一致性校验的结果使用独立来源标记 `local_vlm_consistent`，数值置信度为空；规则与文本评分可继续，保留核对提示。该标记不等于教师确认，更不会自动进入教师训练集。
- 不确定、截断、无效 JSON、空白无法判定、服务断开都保留缺分。候选与第二次转写、局部原图可在识别详情查看，再人工校正。
- 精确图像缓存包含模型 digest、提示版本、区域类型和核验策略。请求 ID 与本地输入/输出 token 存于诊断；缓存命中不重复统计推理请求。这里有本地生成 token，但没有远程识别 token 账单，评分 API 用量仍单独统计。

## 中文填空转写修正（v3-text-3）

修正按题干话题误分类的问题：讨论程序的填空、运行结果和中文术语不再仅因出现“程序”就按代码处理。窄行文字图像保持比例放大并加白边，不擦除下划线或笔迹；这不能恢复原图已丢失的笔画。中文转写提示单独强调逐字识别、不得用正确术语补写答案。

含括号小问编号前缀的文字转写保留候选并提示核对，不自动删编号，也不因两次一致直接采用。新缓存版本与旧版隔离；已有作答和人工成绩不自动覆盖。在识别详情中点击“重新识别预览”，可用当前本地流程重读已有裁切，仅返回候选，核对后需在作答编辑区保存。

两条已人工查看的中文局部图实测：“顺序结构”转写正确；另一条仍把印刷“(2)”混入“选择结构”，已被前缀校验拦截。此小样本只能验证处理路径与错误拦截，不能证明整体识别准确率提高。当前4B模型仍可能错字、漏字或重复同一种错误；换用更强或专用模型需要实际错例及人工转写对照。单纯蒸馏不保证纠正教师模型的这些错误。

用户补充的三处错例对照：v3-text-3 的4B模型将“存储器”识别正确；“思维”仍多一个句点；划掉的旧答案仍被误转成公式，但新增 `has_deletions` 检测在此例触发，结果转为待核对。检测到删除内容一律要求核对；没有检测到不代表证明无涂改。该字段用于保留缺分，不用于自动推断最后一个数字就是答案。

独立 PP-OCRv5 对同三处裁切，前两处文字正确，涂改处错误且分数较低。实测前发现本机CPU路径存在 Paddle PIR/oneDNN 属性转换报错，已对CPU路径停用MKLDNN；GPU路径不受影响。OCR分数不是校准后的正确概率。

本机另行安装官方 `qwen3-vl:8b-instruct` Q4_K_M（语言与视觉组件合计约6.2GB，下载通过Ollama SHA256校验），将本项目本地设置切为8B，不改变评分API模型。8B对“存储器”“思维”均逐字正确；涂改处仍读成 `3Fattt) 6`，检测到涂改后保留候选、不得自动采用。仅此三个指定错例不能代表其他答卷的准确率。首个8B请求曾未完整结束并被拒绝，后续完整请求及“存储器”标准参数复测成功；未将该失败宣称为已证明消除的问题。

8B对后续单个中文裁切的两次推理实测约6秒（已加载模型），不是整题或整班耗时承诺；首次加载、区域数和代码输出会改变耗时。保留4B模型供切换。已有可靠作答不自动覆盖；历史上误合并的填空区域在重新识别预览时也按空分别处理。涂改题需对照原图校正最终作答，再重批缺分题。

可用 `scripts/verify-local-vision.py --cases-file 本地用例.json --model 本地模型名 --output 本地报告.json` 对照已下载模型，不更改默认模型。用例为数组，每项包含 `name`、`path`、`question`、可选 `expected`；相对图像路径相对于用例文件。人工 `expected` 仅在推理后比较，题目中的答案字段不传入模型；用例、图片与报告保存在忽略目录，不作为自动训练标签。

## 能否蒸馏成更小的模型

可以，但先验证教师转写质量，不能直接拿未经核验的转写大量训练。建议分两条实验：

1. 短文字、数字、填空：对现成 PP-OCR 识别器做领域微调或蒸馏，学习“局部图像→逐字文本”。不用生成整个文档结构，通常更适合作为速度优化方向，但效果要实测。
2. 代码、公式、流程图：以现成的小型视觉语言模型（例如 Qwen3-VL 2B）作为学生，学习“裁切→原样转写＋结构 JSON”。只用文本小模型或 MacBERT 无法直接读取图片，不能承担这部分视觉识别。

教师可用经过验证的更强视觉模型，或经过人工修正的当前模型输出；当前 4B 量化模型不是天然可靠的教师。优先人工核验错误代码、涂改、缩进和箭头关系。OCR 标签必须忠实保留学生错误；不能用标准答案或执行后修复的程序替代。

按学生/书写者、试卷与模板划分训练集和留出测试集，避免同一笔迹或同一页面裁切同时出现在两边。分别比较字符错误率、完整答案匹配、代码符号及缩进保真、流程图节点和连接匹配，以及端到端延迟、峰值显存和人工校正比例。样本量由覆盖程度与学习曲线决定，不承诺固定数量即可达到目标。

蒸馏识别与蒸馏评分是两个任务。评分训练还需教师认可的采分点或分数；本轮没有此类数据，不训练评分模型，不自动生成额外训练数据，不重新添加已删除的导出入口。

## 当前实测与限制

工程回归结果在交付报告中记录；它验证程序行为，不等同于 OCR 准确率。已在 RTX 4060 8GB、Vulkan 运行时进行以下本地真实推理，未调用远程视觉 API，未写入分数：

| 样本 | 两次转写耗时 | 观察 |
|---|---:|---|
| 已知内容的合成代码图 | 111.36 秒（含首次加载） | 第一遍与原文一致，第二遍丢缩进，拦截 |
| 实际手写填空第一个区域 | 66.64 秒 | 两次一致，候选可读；无教师真值，不报告准确率 |
| 实际手写填空第二个区域 | 71.69 秒 | 两次一致，候选可读；无教师真值，不报告准确率 |
| 实际编程题区域 | 238.94 秒 | 文字及符号有分歧，保留待校正 |
| 实际流程图题区域 | 733.35 秒 | 存在两次重复漏掉实际处理框的问题；不能据一致性认证完整图结构 |

这些单区耗时不能外推整班吞吐，机器当时还有其他 GPU 进程；未完成 CUDA 与 Vulkan 的对照性能测试。当前 4B 量化模型尚未满足“代码、流程图全部自动可靠转写”的要求。交付的是可运行的本地识别、候选核对及保守采纳流程，不是已验证的全自动高准确率模型。

单区域真实测试记录来自 v1 提示与核验；发现图结构漏识别后，v2 明确禁止流程图自动采纳，并升级缓存版本。跨区域联合输入已通过模拟接口与裁切集成测试，尚未做有教师真值的真实评测。后续如果比较更强的本地模型或显式授权的视觉 API 教师，仍需保留独立人工转写对照；本轮没有开展该对照或蒸馏训练。

启动器已使用无学生资料、无密钥的隔离数据库验证：启用后自动启动本地视觉服务，模型检查 ready=true；退出批改服务后清理自己启动的视觉服务。复用用户已启动的视觉服务时不取得其生命周期所有权。原版 59 个源码文件哈希保持不变。

最终完整工程回归：291 passed，1 skipped（31.24 秒）。包含原流程、原版回退、新来源的规则/文本评分路由、无伪造数值置信度、转写分歧保留缺分、流程图始终人工核对、跨区域同题联合输入、原图访问边界、模型版本缓存、代码缩进差异、安全显示与人工校正保留。测试使用合成数据与模拟模型；上述真实推理另行记录，不混为识别准确率。所有本轮启动的临时验证服务已关闭，用户自己的 8001 服务未被重启。

# 日常评分缺分与重复重试

日期：2026-10-28。

## 已确认的处理缺陷

旧版日常评分将 HTTP 请求成功与评分结果有效分开处理，但单题评分失败后没有保留异常详情，只显示 `llm_request_failed`。因此用户无法分辨网络错误、输出格式错误、分数越界和证据验证失败，再次重试可能持续触发相同问题。

此外，单题返回即使有范围内的合法分数，只要证据不是学生答案中逐字一致的短片段，也会被整项拒收。编程题的空格、换行变化，以及模型将分析解释写入 evidence 都可能触发这一条件。历史记录没有保存原返回和异常，不能据此追认某次失败的具体原因或恢复其分数。

## 本次修复

- 单题请求：数值、范围及必要字段合法时，证据不匹配不再单独导致缺分或第二次请求。删除无法核验的引文，保留建议分，并明确标记 `grading_evidence_unverified`、建议复核。这不代表教师确认，也不进入可自动复用的评分缓存。
- 多学生合并请求：继续严格检查证据归属，避免串学生；异常项仍最多单独补请求一次。单独补请求可按上一条保留合法建议分。
- 无效分数、缺少必要字段、无法解析 JSON 和请求失败仍不能编造分数。限定的重试失败后，保存异常类型与简短详情，写入失败统计。
- 复核界面在缺分原因处直接显示新错误；旧记录明确提示没有保留具体错误，避免只显示笼统的“模型调用失败”。

本轮不额外调用付费 API，不重算用户已有成绩。后台服务需由用户重启后，再只重试缺分题；旧进程不会因文件变化自动载入修复。
